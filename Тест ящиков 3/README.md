# Рефакторинг DesktopPhysics

В этом варианте ответственность разделена на классы:

- `Program.cs` — композиция компонентов и основной цикл.
- `Physics/PhysicsWorldService.cs` — VelcroPhysics, коробки, физические границы и препятствия-окна.
- `Input/InputController.cs` — глобальная клавиатура/мышь, создание, перетаскивание и бросок коробок.
- `Rendering/RaylibRenderer.cs` — загрузка ресурсов Raylib и отрисовка.
- `Windows/Win32WindowProvider.cs` — WinAPI и фоновое сканирование окон Windows.
- `Models/WindowData.cs` — неизменяемый снимок геометрии окна.

## Подключение

1. Сделайте резервную копию проекта.
2. Скопируйте папки и файлы из архива в проект.
3. Удалите старые файлы `Program.cs`, `Program.Main.cs`, `Program.Input.cs`, `Program.Rendering.cs`, `WindowData.cs`, чтобы не было повторных определений.
4. Проверьте, что ресурсы `Arial.ttf` и `resources/box.gif` копируются в каталог запуска.
5. Включите `AllowUnsafeBlocks` в `.csproj`, поскольку декодирование кадров GIF использует `unsafe`.
6. Соберите и запустите проект на Windows.

## Важные замечания

- Все изменения физического мира выполняются в основном цикле. Фоновый поток только сканирует окна и публикует снимок геометрии.
- Коллайдеры внешних окон перестраиваются, только когда изменился список геометрии, а не каждый кадр.
- Это промежуточный рефакторинг: следующий шаг — заменить передачу конкретных классов интерфейсами, добавить очередь команд между WPF и симуляцией и выделить игровые объекты в `Scene`.
- В исходной логике сравнение геометрии не различает два разных окна с одинаковыми размерами и координатами. Для надёжной синхронизации при дальнейшей доработке стоит включить `HWND` в `WindowData`.
- Окно overlay и преобразование координат здесь сохраняют приближение исходного кода. При работе с несколькими мониторами или DPI scaling потребуется отдельно учесть смещение рабочей области и DPI.
