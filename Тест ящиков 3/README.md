# Рефакторинг DesktopPhysics

В этом варианте ответственность разделена на классы:

- `Program.cs` — композиция компонентов и основной цикл.
- `Physics/PhysicsWorldService.cs` — VelcroPhysics, коробки, физические границы и препятствия-окна.
- `Input/InputController.cs` — глобальная клавиатура/мышь, создание, перетаскивание и бросок коробок.
- `Rendering/RaylibRenderer.cs` — загрузка ресурсов Raylib и отрисовка.
- `Windows/Win32WindowProvider.cs` — WinAPI и фоновое сканирование окон Windows.
- `Models/WindowData.cs` — неизменяемый снимок геометрии окна.

## Подключение

1. Сделайте резервную копию проекта.
2. Скопируйте папки и файлы из архива в проект.
3. Удалите старые файлы `Program.cs`, `Program.Main.cs`, `Program.Input.cs`, `Program.Rendering.cs`, `WindowData.cs`, чтобы не было повторных определений.
4. Проверьте, что ресурсы `Arial.ttf` и `resources/box.gif` копируются в каталог запуска.
5. Включите `AllowUnsafeBlocks` в `.csproj`, поскольку декодирование кадров GIF использует `unsafe`.
6. Соберите и запустите проект на Windows.

## Важные замечания

- Все изменения физического мира выполняются в основном цикле. Фоновый поток только сканирует окна и публикует снимок геометрии.
- Коллайдеры внешних окон перестраиваются, только когда изменился список геометрии, а не каждый кадр.
- Это промежуточный рефакторинг: следующий шаг — заменить передачу конкретных классов интерфейсами, добавить очередь команд между WPF и симуляцией и выделить игровые объекты в `Scene`.
- В исходной логике сравнение геометрии не различает два разных окна с одинаковыми размерами и координатами. Для надёжной синхронизации при дальнейшей доработке стоит включить `HWND` в `WindowData`.
- Окно overlay и преобразование координат здесь сохраняют приближение исходного кода. При работе с несколькими мониторами или DPI scaling потребуется отдельно учесть смещение рабочей области и DPI.

## Следующий этап: сцена и игровые объекты

Добавлен небольшой слой сцены:
- `Scene/GameObject.cs` — единый объект сцены с ID, типом, физическим телом и размерами;
- `Scene/GameObjectFactory.cs` — создание объектов по типу;
- `Scene/Scene.cs` — список объектов сцены и очистка;
- ввод создаёт и очищает объекты через `Scene`, а рендерер рисует `Scene.Objects`.

Сейчас реализован только `GameObjectKind.Box`. Это намеренно: следующие типы (персонаж, декорации, другие физические предметы) можно добавлять в фабрику и рендерер поэтапно. WPF/MVVM и настройки пока не подключены.

## Следующий этап: жизненный цикл объектов

- `IGameObjectBehavior` задаёт методы `Update` и `OnRemoved`.
- `GameObject.Update` и `GameObject.NotifyRemoved` передают события поведению объекта.
- `Scene.Update` вызывает поведение объектов каждый кадр; перебор выполняется по снимку списка, чтобы безопаснее переносить создание/удаление из поведения.
- `Scene.Remove` удаляет один объект, уведомляет поведение и удаляет его физическое тело.
- `Delete` удаляет объект под курсором; `X` очищает все коробки.

Пока у коробки `EmptyBehavior`, потому что отдельная логика персонажа или иных объектов ещё не реализована. Физические тела всё ещё принадлежат `PhysicsWorldService`, а жизненный цикл сущностей — `Scene`.

## Отслеживание окон: дифференциальное обновление

- Окно идентифицируется по HWND (`WindowData.Handle`), а не только по размерам/координатам.
- `Win32WindowProvider.Update()` вызывается каждый кадр: уже известные HWND проверяются на закрытие, сворачивание, видимость и изменение геометрии. Полный поиск новых окон выполняется раз в секунду.
- `PhysicsWorldService.SetWindowObstacles` сохраняет тела в словаре HWND → Body.
- Новое окно: создаётся одно статическое физическое тело.
- Окно исчезло: удаляется только его тело.
- Окно переместилось без изменения размеров: существующее тело перемещается через `Body.SetTransform(...)`.
- Изменился размер: пересоздаётся только тело этого окна, а не все оконные препятствия.

Примечание: в текущем снимке координаты переводятся в метры через 50 px/m. Для многоэкранной конфигурации и DPI scaling нужно отдельно согласовать систему координат overlay и координаты Win32.
